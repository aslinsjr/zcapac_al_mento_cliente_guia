📘 Guia Explicativo - Programa ABAP

Consulta de Clientes - Um guia completo para iniciantes

📋 Visão Geral do Programa
▶
Nome: ZCAPAC_JL_MENTO_CLIENTE
Objetivo: Consultar e exibir informações de clientes com base em diferentes critérios de seleção.

Este programa ABAP permite consultar informações de clientes no SAP de duas formas:

  • Busca por número de cliente - Permite selecionar um ou mais clientes específicos
  • Busca por localização - Filtra clientes por país e região

Os dados exibidos incluem: número do cliente, nome, organização de vendas, empresa e cidade.

🏗️ Estrutura do Programa
▶

O programa segue o padrão modular ABAP, dividido em 4 arquivos:

ZCAPAC_JL_MENTO_CLIENTE (Principal)
├── ZCAPAC_JL_MENTO_TOP    → Declarações e tipos
├── ZCAPAC_JL_MENTO_EVE    → Eventos da tela
└── ZCAPAC_JL_MENTO_F01    → Sub-rotinas (Forms)
🎯 Por que modularizar?
- Melhor organização do código
- Facilita manutenção
- Permite reutilização
- Segue boas práticas ABAP

Função de cada arquivo:

  • TOP Declara tabelas, tipos e estruturas de dados
  • EVE Controla eventos da tela de seleção
  • F01 Contém a lógica de negócio (Forms)
  • Principal Orquestra o programa e inclui os demais
📄 Arquivo Principal (CLIENTE)
▶

🔹 Cabeçalho

REPORT zcapac_jl_mento_cliente MESSAGE-ID ZCAPAC_JL_01.
  • REPORT - Define o início de um programa executável
  • MESSAGE-ID - Define a classe de mensagens usada no programa

🔹 Include TOP

INCLUDE zcapac_jl_mento_top.
Onde: Logo no início do programa
Função: Inclui as declarações de tabelas e tipos
Por quê: Organização - separa declarações da lógica

🔹 Tela de Seleção - BLOCO 1

SELECTION-SCREEN BEGIN OF BLOCK bloco1 WITH FRAME TITLE text-t01.
  SELECT-OPTIONS: s_kunnr FOR kna1-kunnr MODIF ID m1.
  
  PARAMETERS: p_land1 TYPE kna1-land1 MODIF ID m2,
              p_regio TYPE kna1-regio MODIF ID m2.
SELECTION-SCREEN END OF BLOCK bloco1.

Componentes:

  • s_kunnr - Permite selecionar faixa de números de clientes (MODIF ID m1)
  • p_land1 - Campo para País (MODIF ID m2)
  • p_regio - Campo para Região (MODIF ID m2)
  • MODIF ID - Identificador para controle de exibição dinâmica

🔹 Tela de Seleção - BLOCO 2

SELECTION-SCREEN BEGIN OF BLOCK bloco2 WITH FRAME TITLE text-t02.
  PARAMETERS: r_op1 RADIOBUTTON GROUP r1 USER-COMMAND com1 DEFAULT 'X',
              r_op2 RADIOBUTTON GROUP r1.
SELECTION-SCREEN END OF BLOCK bloco2.
  • r_op1 - Opção 1: Busca por número de cliente (padrão)
  • r_op2 - Opção 2: Busca por país/região
  • USER-COMMAND com1 - Dispara evento ao clicar (atualiza tela)

🔹 Botão de Função

SELECTION-SCREEN FUNCTION KEY 1.

Cria um botão personalizado na tela (F1), configurado no evento INITIALIZATION.

🔹 Eventos do Programa

INCLUDE zcapac_jl_mento_eve.

START-OF-SELECTION.
  PERFORM zf_seleciona_dados.

END-OF-SELECTION.
  INCLUDE zcapac_jl_mento_f01.
⚡ START-OF-SELECTION: Executado ao pressionar F8
📌 PERFORM: Chama a sub-rotina que busca os dados
📦 END-OF-SELECTION: Inclui as sub-rotinas (Forms)
📦 Arquivo TOP (Declarações)
▶

🔹 Tabelas Utilizadas

TABLES: kna1, knvv, knb1, adrc, sscrfields.
  • kna1 - Dados mestres de clientes
  • knvv - Dados de vendas do cliente
  • knb1 - Dados contábeis do cliente
  • adrc - Endereços
  • sscrfields - Campos de controle da tela de seleção

🔹 Estrutura de Saída

BEGIN OF tp_saida,
  cliente  TYPE kna1-kunnr,
  nome     TYPE kna1-name1,
  org_vend TYPE knvv-vkorg,
  empresa  TYPE knb1-bukrs,
  cidade   TYPE adrc-city1,
END OF tp_saida,
💡 Função: Define estrutura final dos dados exibidos
📊 Campos: Cliente, Nome, Organização de Vendas, Empresa, Cidade

🔹 Estrutura KNA1 (Cliente)

BEGIN OF tp_kna1,
  kunnr TYPE kunnr,      → Número do cliente
  name1 TYPE name1_gp,   → Nome
  land1 TYPE land1_gp,   → País
  regio TYPE regio,      → Região
  adrnr TYPE adrnr,      → Número do endereço
END OF tp_kna1,
🎯 Função: Estrutura otimizada para seleção de dados
⚡ Por quê: Busca apenas campos necessários (performance)

🔹 Outras Estruturas

  • tp_knvv → Organização de vendas
  • tp_knb1 → Empresa do cliente
  • tp_adrc → Endereço/Cidade
  • tp_tvarvc_full → Parâmetros de configuração
⚡ Arquivo EVE (Eventos da Tela)
▶

🔹 INITIALIZATION

INITIALIZATION.
  DATA: wl_action TYPE smp_dyntxt.
  
  wl_action-text = text-t03.
  wl_action-icon_text = text-t03.
  wl_action-quickinfo = text-t03.
  wl_action-icon_id = icon_personal_settings.
  
  sscrfields-functxt_01 = wl_action.
⏰ Quando: Antes da tela aparecer (1ª vez)
🎯 Função: Configura o botão F1 com ícone e texto
✅ Resultado: Botão "Configurações Pessoais" aparece na tela

🔹 AT SELECTION-SCREEN ON p_regio

AT SELECTION-SCREEN ON p_regio.
  PERFORM zf_valida_regio.
  • Quando: Ao sair do campo p_regio (região)
  • Função: Valida se a região existe
  • Chama: Form zf_valida_regio

🔹 AT SELECTION-SCREEN

AT SELECTION-SCREEN.
  CASE sy-ucomm.
    WHEN 'FC01'.
      PERFORM zf_exibe_cliente.
  ENDCASE.
  • Quando: Ao clicar em botões da tela
  • sy-ucomm - Código do comando executado
  • FC01 - Código do botão F1
  • Função: Abre tela de cliente (XD03)

🔹 AT SELECTION-SCREEN OUTPUT

AT SELECTION-SCREEN OUTPUT.
  LOOP AT SCREEN.
    IF r_op1 IS NOT INITIAL.
      CASE screen-group1.
        WHEN 'M1'.
          screen-active = 1.  → Ativa campos do grupo M1
        WHEN 'M2'.
          screen-active = 0.  → Desativa campos do grupo M2
      ENDCASE.
    ELSE.
      [... inverso ...]
    ENDIF.
    MODIFY SCREEN.
  ENDLOOP.
⏰ Quando: Antes de exibir a tela (sempre)
🎯 Função: Controla quais campos aparecem
📌 Lógica:
- Se r_op1 marcado → mostra s_kunnr (M1), esconde p_land1/p_regio (M2)
- Se r_op2 marcado → esconde s_kunnr (M1), mostra p_land1/p_regio (M2)
🔧 Arquivo F01 (Sub-rotinas)
▶

🔹 FORM zf_seleciona_dados

Bloco 1: Declarações

DATA: vl_bukrs       TYPE bukrs,
      tl_kna1        TYPE tp_t_kna1,
      tl_knvv        TYPE tp_t_knvv,
      tl_knb1        TYPE tp_t_knb1,
      tl_adrc        TYPE tp_t_adrc,
      tl_tvarvc_full TYPE tp_t_tvarvc_full.

Declara variáveis locais (tabelas internas)

Bloco 2: Busca Parâmetros

SELECT sign opti low high
  INTO TABLE tl_tvarvc_full
  FROM tvarvc
  WHERE name = 'ZCAPAC_JL_BUKRS_S' AND
        type = 'S'.
🎯 Função: Busca empresas permitidas (filtro)
📦 tvarvc: Tabela de variáveis/parâmetros do sistema
💼 Uso posterior: Filtrar clientes por empresa autorizada

Bloco 3: Seleção Condicional

IF r_op1 IS NOT INITIAL.
  SELECT kunnr name1 land1 regio adrnr
    INTO TABLE tl_kna1
    FROM kna1
    WHERE kunnr IN s_kunnr.
ELSE.
  SELECT kunnr name1 land1 regio adrnr
    INTO TABLE tl_kna1
    FROM kna1
    WHERE land1 = p_land1
    AND regio = p_regio.
ENDIF.
  • Opção 1: Busca por número de cliente
  • Opção 2: Busca por país e região

Bloco 4: Seleções Complementares

IF sy-subrc IS INITIAL.
  SELECT kunnr vkorg
    FROM knvv
    INTO TABLE tl_knvv
    FOR ALL ENTRIES IN tl_kna1
    WHERE kunnr EQ tl_kna1-kunnr.
✅ sy-subrc IS INITIAL: Se encontrou clientes
⚡ FOR ALL ENTRIES: Busca dados relacionados aos clientes encontrados
📊 Busca:
- Organização de vendas (knvv)
- Empresa (knb1)
- Endereço/Cidade (adrc)

🔹 FORM zf_trata_dados

Função Principal: Processa os dados brutos e monta estrutura de saída

Lógica do LOOP

LOOP AT ft_kna1 INTO wl_kna1.
  wl_saida-cliente = wl_kna1-kunnr.
  wl_saida-nome    = wl_kna1-name1.
  
  READ TABLE ft_knvv INTO wl_knvv WITH KEY kunnr = wl_kna1-kunnr.
  IF sy-subrc IS INITIAL.
    wl_saida-org_vend = wl_knvv-vkorg.
  ENDIF.

Para cada cliente:

  1. Copia número e nome
  2. Busca organização de vendas (READ TABLE)
  3. Busca empresa (com BINARY SEARCH - mais rápido)
  4. Valida se empresa está autorizada
  5. Busca cidade
  6. Adiciona à tabela de saída (APPEND)

Validação de Empresa

READ TABLE ft_tvarvc TRANSPORTING NO FIELDS WITH KEY low = wl_knb1-bukrs.
IF sy-subrc EQ 0.
  wl_saida-empresa = wl_knb1-bukrs.
ELSE.
  CLEAR wl_saida.
  CONTINUE.  → Pula este cliente
ENDIF.
🎯 Função: Verifica se empresa está na lista autorizada
⏭️ CONTINUE: Ignora cliente se empresa não autorizada

🔹 FORM zf_imprime_dados

LOOP AT ft_output INTO wl_saida.
  WRITE: / 'Cliente:', wl_saida-cliente, 
           'Nome:', wl_saida-nome, 
           'Org. Vendas:', wl_saida-org_vend,
           'Empresa:', wl_saida-empresa, 
           'Cidade:', wl_saida-cidade.
ENDLOOP.
  • WRITE - Comando de saída
  • / - Nova linha

🔹 FORM zf_exibe_cliente

CALL FUNCTION 'POPUP_TO_CONFIRM'
  EXPORTING
    text_question         = text-t07
    text_button_1         = text-t05
    text_button_2         = text-t06
  IMPORTING
    answer                = vl_resposta.

Exibe popup de confirmação: "Deseja imprimir?" com botões Sim/Não

IF vl_resposta EQ cl_resposta-sim.
  SET PARAMETER ID 'KUN' FIELD s_kunnr-low.
  CALL TRANSACTION 'XD03' AND SKIP FIRST SCREEN.
Se SIM:
- Define parâmetro KUN com número do cliente
- Abre transação XD03 (Exibir Cliente)
- SKIP FIRST SCREEN: Pula tela inicial

🔹 FORM zf_valida_regio

CALL FUNCTION 'ZCAPAC_JL_CHECK_REGIO'
  EXPORTING
    iv_regio = p_regio
  IMPORTING
    ev_check = vl_check.

IF vl_check IS INITIAL.
  MESSAGE s004 DISPLAY LIKE 'E' WITH p_regio.
  RETURN.
ENDIF.
  • Função: Valida se região existe
  • Function Module: Função customizada de validação
  • Se inválida: Exibe mensagem de erro e interrompe
🔄 Fluxo de Execução Completo
▶ 
1. USUÁRIO ABRE O PROGRAMA
   ↓
2. INITIALIZATION
   → Configura botão F1
   ↓
3. AT SELECTION-SCREEN OUTPUT
   → Mostra/Esconde campos conforme radio button
   ↓
4. USUÁRIO PREENCHE DADOS
   ↓
5. AT SELECTION-SCREEN ON p_regio (se preenchido)
   → Valida região
   ↓
6. USUÁRIO CLICA EM BOTÃO F1 (opcional)
   → AT SELECTION-SCREEN
   → zf_exibe_cliente
   → Abre XD03
   ↓
7. USUÁRIO PRESSIONA F8 (Executar)
   ↓
8. START-OF-SELECTION
   → zf_seleciona_dados
      ├─ Busca parâmetros (empresas)
      ├─ Busca clientes (kna1)
      ├─ Busca org.vendas (knvv)
      ├─ Busca empresas (knb1)
      ├─ Busca endereços (adrc)
      └─ zf_trata_dados
         ├─ Combina dados
         ├─ Valida empresas
         └─ zf_imprime_dados
            └─ WRITE (exibe na tela)
🎯 Conceitos ABAP Importantes
▶

✅ SELECT com FOR ALL ENTRIES

  • O quê: Busca dados relacionados sem fazer SELECT dentro de LOOP
  • Vantagem: Performance (menos acessos ao banco)

✅ BINARY SEARCH

  • O quê: Busca binária em tabela ordenada
  • Requer: SORT antes do READ TABLE
  • Vantagem: Muito mais rápido

✅ MODIF ID

  • O quê: Agrupa campos para controle dinâmico
  • Uso: AT SELECTION-SCREEN OUTPUT

✅ sy-subrc

  • O quê: Código de retorno de operações
  • 0 ou IS INITIAL: Sucesso
  • Diferente de 0: Erro/Não encontrado

✅ TRANSPORTING NO FIELDS

  • O quê: Busca sem carregar dados
  • Uso: Apenas verificar existência
💡 Dicas para Iniciantes
▶
  1. INCLUDES: Organizam código em arquivos separados
  2. TYPES: Defina estruturas otimizadas (só campos necessários)
  3. FOR ALL ENTRIES: Use para evitar SELECTs em LOOP
  4. SORT + BINARY SEARCH: Sempre que possível
  5. sy-subrc: Sempre verifique após operações críticas
  6. CLEAR: Limpe work areas antes de reusar
  7. MESSAGE-ID: Centralize mensagens em classes

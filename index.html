📘 ZCAPAC_AL_MENTO_CLIENTE

Sistema de Consulta e Gestão de Clientes - Guia Completo

📋 Visão Geral do Programa
▶
Nome: ZCAPAC_AL_MENTO_CLIENTE
Message-ID: ZCAPAC_JL_01
Tipo: Report Executável
Objetivo: Consultar, exibir e gerenciar informações de clientes com filtros avançados e múltiplas opções de visualização.

🎯 Propósito do Programa

Este programa ABAP permite consultar informações de clientes do SAP com duas modalidades de busca e três formas de exibição, incluindo funcionalidades de edição e persistência de dados.

📊 Modalidades de Busca

  • Opção 1 Busca por Cliente - Permite selecionar um ou múltiplos clientes específicos através de range (SELECT-OPTIONS)
  • Opção 2 Busca por Localização - Filtra clientes por país (LAND1) e região (REGIO) com validação de região

🖥️ Formas de Exibição

  • Lista Simples - Formato WRITE tradicional
  • ALV Manual - Grid ALV com fieldcatalog manual
  • ALV Function - Grid ALV com fieldcatalog automático + edição de cidade + salvamento em banco

📦 Dados Exibidos

Cliente (KUNNR) Número identificador do cliente
Nome (NAME1) Razão social do cliente
Org. Vendas (VKORG) Organização de vendas associada
Empresa (BUKRS) Código da empresa (filtrado por TVARVC)
Cidade (CITY1) Cidade do endereço do cliente
🏗️ Estrutura do Programa
▶

O programa segue o padrão modular ABAP, dividido em 4 arquivos INCLUDE:

ZCAPAC_AL_MENTO_CLIENTE (Principal - 42 linhas)
├── ZCAPAC_JL_MENTO_TOP    → Declarações, TYPES e DATA (77 linhas)
├── ZCAPAC_JL_MENTO_EVE    → Eventos da tela de seleção (54 linhas)
└── ZCAPAC_JL_MENTO_F01    → Sub-rotinas/FORMs (320+ linhas)
🎯 Vantagens da Modularização:
✓ Separação clara de responsabilidades
✓ Facilita manutenção e debug
✓ Permite trabalho em equipe
✓ Reutilização de código
✓ Segue boas práticas SAP

📁 Função de cada arquivo:

Arquivo Responsabilidade Conteúdo
CLIENTE Orquestração REPORT, tela de seleção, START-OF-SELECTION
TOP Declarações TABLES, TYPES, DATA globais
EVE Eventos INITIALIZATION, AT SELECTION-SCREEN, OUTPUT
F01 Lógica FORMs com toda lógica de negócio
📄 Arquivo Principal (CLIENTE)
▶

🔹 1. Cabeçalho do Report

REPORT zcapac_jl_mento_cliente MESSAGE-ID ZCAPAC_JL_01.
  • REPORT - Define um programa executável (tipo R)
  • MESSAGE-ID - Define classe de mensagens ZCAPAC_JL_01 para usar MESSAGE s000, e001, etc.

🔹 2. Include TOP (Declarações)

INCLUDE zcapac_jl_mento_top.

Inclui todas as declarações: TABLES, TYPES e variáveis globais.

🔹 3. Tela de Seleção - BLOCO 1

SELECTION-SCREEN BEGIN OF BLOCK bloco1 WITH FRAME TITLE text-t01.
  SELECT-OPTIONS: s_kunnr FOR kna1-kunnr MODIF ID m1.

  PARAMETERS: p_land1 TYPE kna1-land1 MODIF ID m2,
              p_regio TYPE kna1-regio MODIF ID m2.
SELECTION-SCREEN END OF BLOCK bloco1.
SELECT-OPTIONS s_kunnr: Range de clientes (permite múltiplos valores, intervalos, exclusões)
PARAMETERS p_land1/p_regio: Campos simples para país e região
MODIF ID m1/m2: Grupos de modificação para controle dinâmico de tela

🔹 4. Tela de Seleção - BLOCO 2

SELECTION-SCREEN BEGIN OF BLOCK bloco2 WITH FRAME TITLE text-t02.
  PARAMETERS: r_op1 RADIOBUTTON GROUP r1 USER-COMMAND com1 DEFAULT 'X',
              r_op2 RADIOBUTTON GROUP r1.

  SELECTION-SCREEN SKIP 1.
  
  PARAMETERS: p_alv    TYPE c AS CHECKBOX DEFAULT 'X',
              p_manual TYPE c AS CHECKBOX DEFAULT ''.
SELECTION-SCREEN END OF BLOCK bloco2.
  • r_op1/r_op2 - Radiobuttons para escolher modo de busca
  • USER-COMMAND com1 - Dispara evento AT SELECTION-SCREEN OUTPUT para controlar visibilidade
  • p_alv - Checkbox para usar ALV (marcado por padrão)
  • p_manual - Checkbox para usar fieldcatalog manual

🔹 5. Botões de Função

SELECTION-SCREEN FUNCTION KEY 1.
SELECTION-SCREEN FUNCTION KEY 2.

Cria 2 botões customizados na barra de ferramentas (FC01 e FC02).

🔹 6. Include Eventos

INCLUDE zcapac_jl_mento_eve.

Inclui todos os eventos: INITIALIZATION, AT SELECTION-SCREEN, etc.

🔹 7. Processamento Principal

START-OF-SELECTION.
  PERFORM zf_seleciona_dados.

END-OF-SELECTION.
  INCLUDE zcapac_jl_mento_f01.
  • START-OF-SELECTION - Evento disparado após validação da tela
  • PERFORM zf_seleciona_dados - Chama FORM principal que inicia processamento
  • Include F01 no final (poderia ser no início também)

  wl_action-text = text-t03.

  CLEAR wl_action.
  wl_action-text = text-t04.
  wl_action-icon_text = text-t04.

  wl_action-icon_id = icon_assign.
  sscrfields-functxt_02 = wl_action.
  • Configura FC01 com ícone de configurações pessoais
  • Configura FC02 com ícone de atribuição
  • Textos vêm de text-symbols

🔹 2. AT SELECTION-SCREEN ON p_regio

Valida campo região quando usuário sair dele (validação de campo).

AT SELECTION-SCREEN ON p_regio.
  PERFORM zf_valida_regio.

Chama FORM que valida se região existe usando function module customizada.

🔹 3. AT SELECTION-SCREEN

Executado quando usuário clica nos botões de função.

AT SELECTION-SCREEN.
  CASE sy-ucomm.
    WHEN 'FC01'.
      PERFORM zf_exibe_cliente.  "Exibe transação XD03
    WHEN 'FC02'.
      PERFORM zf_exibe_stvarv.   "Exibe transação STVARV
  ENDCASE.
  • sy-ucomm - Contém o código do botão pressionado
  • FC01 - Abre dados do cliente
  • FC02 - Abre manutenção de variáveis

🔹 4. AT SELECTION-SCREEN OUTPUT

Controla visibilidade de campos baseado em radiobuttons.

AT SELECTION-SCREEN OUTPUT.
  LOOP AT SCREEN.
    IF r_op1 IS NOT INITIAL.
      CASE screen-group1.
        WHEN 'M1'.
          screen-active = 1.  "Mostra s_kunnr
        WHEN 'M2'.
          screen-active = 0.  "Esconde p_land1/p_regio
      ENDCASE.
    ELSE.
      CASE screen-group1.
        WHEN 'M1'.
          screen-active = 0.  "Esconde s_kunnr
        WHEN 'M2'.
          screen-active = 1.  "Mostra p_land1/p_regio
      ENDCASE.
    ENDIF.
    MODIFY SCREEN.
  ENDLOOP.
Lógica:
• Se r_op1 marcado → Mostra s_kunnr (M1), esconde p_land1/p_regio (M2)
• Se r_op2 marcado → Esconde s_kunnr (M1), mostra p_land1/p_regio (M2)
Efeito: Tela dinâmica que se adapta à opção escolhida
⚙️ Arquivo F01 (Forms)
▶

🔹 FORM zf_seleciona_dados

Propósito: Buscar dados de clientes e tabelas relacionadas.

1. Busca Parâmetros Sistema (TVARVC)

SELECT sign opti low high
  INTO TABLE tl_tvarvc_full
  FROM tvarvc
  WHERE name = 'ZCAPAC_JL_BUKRS_S' AND type = 'S'.

Busca lista de empresas permitidas configuradas em TVARVC.

2. Busca Clientes (KNA1)

IF r_op1 IS NOT INITIAL.
  SELECT kunnr name1 land1 regio adrnr
    INTO TABLE tl_kna1
    FROM kna1
    WHERE kunnr IN s_kunnr.
ELSE.
  SELECT kunnr name1 land1 regio adrnr
    INTO TABLE tl_kna1
    FROM kna1
    WHERE land1 = p_land1
    AND regio = p_regio.
ENDIF.

Busca de acordo com opção: por número cliente OU por país/região.

3. Busca Org. Vendas (KNVV)

SELECT kunnr vkorg
  FROM knvv
  INTO TABLE tl_knvv
  FOR ALL ENTRIES IN tl_kna1
  WHERE kunnr EQ tl_kna1-kunnr.

4. Busca Empresas (KNB1)

SELECT kunnr bukrs
  FROM knb1
  INTO TABLE tl_knb1
  FOR ALL ENTRIES IN tl_kna1
  WHERE kunnr EQ tl_kna1-kunnr.

IF sy-subrc IS INITIAL.
  SORT tl_knb1 BY kunnr.
ENDIF.

Ordena para usar BINARY SEARCH depois.

5. Busca Endereços (ADRC)

SELECT addrnumber city1
  INTO TABLE tl_adrc
  FROM adrc
  FOR ALL ENTRIES IN tl_kna1
  WHERE addrnumber EQ tl_kna1-adrnr.

IF sy-subrc IS INITIAL.
  SORT tl_adrc BY addrnumber.
ENDIF.

6. Processa Dados

PERFORM zf_trata_dados USING tl_kna1 tl_knvv tl_knb1 tl_adrc tl_tvarvc_full.
⚠️ FOR ALL ENTRIES: Técnica essencial para evitar SELECTs dentro de LOOP. Cuidado: sempre verificar se tabela interna não está vazia antes!

🔹 FORM zf_trata_dados

Propósito: Combinar dados de todas as tabelas em estrutura de saída.

LOOP AT ft_kna1 INTO wl_kna1.
  wl_saida-kunnr = wl_kna1-kunnr.
  wl_saida-name1 = wl_kna1-name1.

  "Busca org. vendas
  READ TABLE ft_knvv INTO wl_knvv WITH KEY kunnr = wl_kna1-kunnr.
  IF sy-subrc IS INITIAL.
    wl_saida-vkorg = wl_knvv-vkorg.
  ENDIF.

  "Busca empresa
  READ TABLE ft_knb1 INTO wl_knb1 
    WITH KEY kunnr = wl_kna1-kunnr BINARY SEARCH.
  IF sy-subrc IS INITIAL.
    "Verifica se empresa está na TVARVC
    READ TABLE ft_tvarvc TRANSPORTING NO FIELDS 
      WITH KEY low = wl_knb1-bukrs.
    IF sy-subrc EQ 0.
      wl_saida-empresa = wl_knb1-bukrs.
    ELSE.
      CLEAR wl_saida.
      CONTINUE.  "Pula cliente se empresa não autorizada
    ENDIF.
  ELSE.
    CLEAR wl_saida.
    CONTINUE.
  ENDIF.

  "Busca cidade
  READ TABLE ft_adrc INTO wl_adrc 
    WITH KEY addrnumber = wl_kna1-adrnr BINARY SEARCH.
  IF sy-subrc IS INITIAL.
    wl_saida-cidade = wl_adrc-city1.
  ENDIF.

  APPEND wl_saida TO tl_saida.
  CLEAR wl_saida.
ENDLOOP.
✓ FILTRO IMPORTANTE: Apenas clientes cuja empresa (BUKRS) está na tabela TVARVC são incluídos no resultado. CONTINUE pula registros não autorizados.

Decisão de Exibição

IF tl_saida IS NOT INITIAL.
  IF p_alv IS NOT INITIAL.
    PERFORM zf_monta_alv USING tl_saida ft_knvv.
  ELSE.
    PERFORM zf_imprime_dados USING tl_saida.
  ENDIF.
ELSE.
  MESSAGE e001.  "Não há dados
ENDIF.

🔹 FORM zf_imprime_dados

Propósito: Exibir dados em formato lista simples (WRITE).

LOOP AT ft_output INTO wl_saida.
  WRITE: / 'Cliente:', wl_saida-kunnr, 
           'Nome:', wl_saida-name1, 
           'Org. Vendas:', wl_saida-vkorg,
           'Empresa:', wl_saida-empresa, 
           'Cidade:', wl_saida-cidade.
ENDLOOP.

🔹 FORM zf_monta_alv

Propósito: Montar e exibir ALV Grid.

Preparação dos Dados

tg_alv[] = ft_output[].  "Para ALV manual

LOOP AT ft_output INTO DATA(wl_output).
  CLEAR wl_alv2.
  MOVE-CORRESPONDING wl_output TO wl_alv2.
  wl_alv2-bukrs = wl_output-empresa.
  wl_alv2-city1 = wl_output-cidade.
  APPEND wl_alv2 TO tg_alv_2[].
ENDLOOP.

Filtro Específico

IF p_manual IS INITIAL.
  LOOP AT tg_alv_2[] INTO wl_alv2.
    vl_tabix = sy-tabix.
    IF wl_alv2-kunnr = '0000023425'.
      DELETE tg_alv_2 INDEX sy-tabix.
    ENDIF.
  ENDLOOP.
ENDIF.

Remove cliente específico hardcoded quando não é modo manual.

Exibição ALV

IF p_manual IS INITIAL.
  vl_command = 'USERCOMMAND'.
  PERFORM zf_monta_fieldcat_function CHANGING tl_fieldcat.
  
  CALL FUNCTION 'REUSE_ALV_GRID_DISPLAY'
    EXPORTING
      i_callback_program      = sy-cprog
      it_fieldcat             = tl_fieldcat
      i_callback_user_command = vl_command
    TABLES
      t_outtab = tg_alv_2[]
    EXCEPTIONS
      program_error = 1
      OTHERS = 2.
ELSE.
  PERFORM zf_monta_fieldcat CHANGING tl_fieldcat.
  
  CALL FUNCTION 'REUSE_ALV_GRID_DISPLAY'
    EXPORTING
      i_callback_program = sy-cprog
      it_fieldcat = tl_fieldcat
    TABLES
      t_outtab = tg_alv[]
    EXCEPTIONS
      program_error = 1
      OTHERS = 2.
ENDIF.

🔹 FORM zf_monta_fieldcat

Propósito: Criar fieldcatalog manualmente.

wl_fieldcat-fieldname = 'CLIENTE'.
wl_fieldcat-datatype = 'KUNNR'.
wl_fieldcat-col_pos = '1'.
wl_fieldcat-seltext_s = text-t08.
wl_fieldcat-seltext_m = text-t08.
wl_fieldcat-seltext_l = text-t08.
APPEND wl_fieldcat TO ct_fieldcat[].

Repete para todos os campos: CLIENTE, NOME, ORG_VENDA, EMPRESA, CIDADE.

🔹 FORM zf_monta_fieldcat_function

Propósito: Criar fieldcatalog automaticamente e customizar.

1. Gera Fieldcatalog Automático

CALL FUNCTION 'REUSE_ALV_FIELDCATALOG_MERGE'
  EXPORTING
    i_structure_name = 'ZST_CAPAC_JL_01'
  CHANGING
    ct_fieldcat = ct_fieldcat.

2. Customiza Campos

LOOP AT ct_fieldcat ASSIGNING FIELD-SYMBOL(<fs_fieldcat2>).
  CASE <fs_fieldcat2>-fieldname.
    WHEN 'CITY1'.
      <fs_fieldcat2>-edit = abap_true.  "Permite edição
    WHEN 'VKORG' OR 'BUKRS'.
      <fs_fieldcat2>-no_out = abap_true.  "Oculta colunas
    WHEN 'KUNNR'.
      <fs_fieldcat2>-seltext_s = text-t13.  "Muda texto
      <fs_fieldcat2>-seltext_m = text-t13.
      <fs_fieldcat2>-seltext_l = text-t13.
  ENDCASE.
ENDLOOP.
📝 Campo Editável: CITY1 pode ser editado diretamente no ALV. Colunas VKORG e BUKRS ficam ocultas mas permanecem na estrutura de dados.

🔹 FORM usercommand

Propósito: Capturar evento de salvamento no ALV e gravar no banco.

FORM usercommand USING r_ucomm LIKE sy-ucomm
                       rs_selfield TYPE slis_selfield.

  IF r_ucomm EQ '&DATA_SAVE'.
    LOOP AT tg_alv_2 INTO DATA(wl_alv).
      wl_clientes-kunnr = wl_alv-kunnr.
      wl_clientes-name1 = wl_alv-name1.
      wl_clientes-bukrs = wl_alv-bukrs.
      APPEND wl_clientes TO tl_clientes[].
    ENDLOOP.

    IF tl_clientes[] IS NOT INITIAL.
      MODIFY zcapac_jl_prog FROM TABLE tl_clientes[].
      IF sy-subrc EQ 0.
        COMMIT WORK.
      ELSE.
        ROLLBACK WORK.
      ENDIF.
    ENDIF.
  ENDIF.
ENDFORM.
💾 Salvamento: Quando usuário clica em salvar no ALV (&DATA_SAVE), dados editados são gravados na tabela customizada ZCAPAC_JL_PROG com controle de transação.

🔹 FORM zf_exibe_cliente

Propósito: Exibir transação XD03 para o cliente selecionado.

CALL FUNCTION 'POPUP_TO_CONFIRM'
  EXPORTING
    text_question = text-t07
    text_button_1 = text-t05
    text_button_2 = text-t06
    default_button = '1'
    display_cancel_button = 'X'
  IMPORTING
    answer = vl_resposta
  EXCEPTIONS
    text_not_found = 1
    OTHERS = 2.

IF sy-subrc EQ 0.
  IF vl_resposta EQ cl_resposta-sim.
    SET PARAMETER ID 'KUN' FIELD s_kunnr-low.
    CALL TRANSACTION 'XD03' AND SKIP FIRST SCREEN.
  ELSE.
    RETURN.
  ENDIF.
ENDIF.
  • Mostra popup de confirmação
  • Se sim: Preenche parâmetro KUN e chama XD03 (exibir cliente)
  • SKIP FIRST SCREEN pula tela inicial da transação

🔹 FORM zf_valida_regio

Propósito: Validar se região existe.

CALL FUNCTION 'ZCAPAC_JL_CHECK_REGIO'
  EXPORTING
    iv_regio = p_regio
  IMPORTING
    ev_check = vl_check.

IF vl_check IS INITIAL.
  MESSAGE s004 DISPLAY LIKE 'E' WITH p_regio.
  RETURN.
ENDIF.

Usa function module customizada para validação. Se inválida, exibe mensagem.

🔹 FORM zf_exibe_stvarv

Propósito: Abrir transação de manutenção de variáveis.

CALL TRANSACTION 'STVARV'.

Simples chamada à transação STVARV para manutenção de TVARVC.

🔄 Fluxo de Execução Completo
▶

📊 Diagrama de Fluxo


1. INITIALIZATION
   └─> Configura botões FC01 e FC02
   
2. Usuário preenche tela
   └─> Marca r_op1 ou r_op2
   └─> Preenche s_kunnr OU p_land1/p_regio
   └─> Marca/desmarca p_alv e p_manual
   
3. AT SELECTION-SCREEN OUTPUT
   └─> Mostra/esconde campos conforme radiobutton
   
4. AT SELECTION-SCREEN ON p_regio
   └─> Valida região (se preenchida)
   
5. Usuário pode clicar FC01 ou FC02
   AT SELECTION-SCREEN
   ├─> FC01: Popup + XD03
   └─> FC02: Abre STVARV
   
6. Usuário executa (F8)
   START-OF-SELECTION
   └─> PERFORM zf_seleciona_dados
       ├─> SELECT TVARVC (empresas permitidas)
       ├─> SELECT KNA1 (clientes)
       ├─> SELECT KNVV (org. vendas)
       ├─> SELECT KNB1 (empresas)
       ├─> SELECT ADRC (endereços)
       └─> PERFORM zf_trata_dados
           ├─> LOOP clientes
           ├─> READ vendas, empresas, endereços
           ├─> Filtra por empresa TVARVC
           └─> Monta tabela saída
           
7. Exibição
   ├─> Se p_alv desmarcado
   │   └─> PERFORM zf_imprime_dados
   │       └─> WRITE lista simples
   │
   └─> Se p_alv marcado
       └─> PERFORM zf_monta_alv
           ├─> Prepara tg_alv ou tg_alv_2
           ├─> Remove cliente '0000023425' (se não manual)
           │
           ├─> Se p_manual marcado
           │   └─> zf_monta_fieldcat (manual)
           │       └─> REUSE_ALV_GRID_DISPLAY
           │
           └─> Se p_manual desmarcado
               └─> zf_monta_fieldcat_function (automático)
                   ├─> REUSE_ALV_FIELDCATALOG_MERGE
                   ├─> Customiza: CITY1 editável, oculta VKORG/BUKRS
                   └─> REUSE_ALV_GRID_DISPLAY com USERCOMMAND
                   
8. No ALV Function (se usuário editar e salvar)
   FORM usercommand
   └─> Captura &DATA_SAVE
       └─> MODIFY zcapac_jl_prog
           ├─> COMMIT WORK (sucesso)
           └─> ROLLBACK WORK (erro)

Validação AT SELECTION-SCREEN ON Valida região
Botões Custom FUNCTION KEY + AT SELECTION-SCREEN Acesso rápido XD03/STVARV

4️⃣ Técnicas de Performance

  • FOR ALL ENTRIES: Substitui SELECTs em LOOP 
    SELECT campos FROM tabela
  FOR ALL ENTRIES IN tabela_interna
  WHERE campo = tabela_interna-campo.
  • BINARY SEARCH: Busca rápida (requer SORT antes) 
    SORT tabela BY campo.
READ TABLE tabela ... BINARY SEARCH.
  • TRANSPORTING NO FIELDS: Apenas verifica existência 
    READ TABLE tabela TRANSPORTING NO FIELDS WITH KEY ...
  • TYPES customizados: Apenas campos necessários (não SELECT *)

💡 Dicas e Boas Práticas
▶

✅ Organização de Código

  1. Modularize: Use INCLUDEs para separar declarações, eventos e lógica
  2. Nomeação Clara: Prefixos z*, nomes descritivos (zf_seleciona_dados)
  3. Comentários: Documente FORMs e lógica complexa
  4. Indentação: Mantenha código legível

✅ Performance

  1. Evite SELECT em LOOP: Use FOR ALL ENTRIES
  2. Use BINARY SEARCH: Após SORT de tabela interna
  3. Selecione apenas campos necessários: Crie TYPES customizados
  4. TRANSPORTING NO FIELDS: Quando só precisa verificar existência
  5. WHERE em SELECT: Filtre no banco, não na aplicação

✅ Validações

  1. Sempre verifique sy-subrc: Após SELECT, READ TABLE, CALL FUNCTION
  2. IS NOT INITIAL antes de FOR ALL ENTRIES: Evita erro se tabela vazia
  3. Valide campos na tela: AT SELECTION-SCREEN ON campo
  4. Mensagens claras: Use MESSAGE-ID e text-symbols

✅ ALV

  1. Fieldcatalog Automático: Mais rápido e consistente com DDIC
  2. Customize após gerar: Modifique edit, no_out, textos
  3. USERCOMMAND: Para capturar eventos (salvar, clique, etc)
  4. Tabela global: Para USERCOMMAND acessar dados

✅ Tela de Seleção

  1. MODIF ID: Agrupe campos para controle em bloco
  2. USER-COMMAND: Dispare eventos ao mudar radiobutton
  3. DEFAULT valores: Facilite uso com valores padrão
  4. Text-symbols: Textos traduzíveis (text-t01, text-t02)

✅ Banco de Dados

  1. MODIFY vs INSERT/UPDATE: MODIFY tenta UPDATE, se falhar faz INSERT
  2. FROM TABLE: Mais rápido que LOOP + INSERT individual
  3. COMMIT/ROLLBACK: Controle transacional explícito
  4. Verifique sy-subrc após MODIFY: Para saber se teve sucesso

⚠️ Pontos de Atenção

  • Cliente hardcoded: Remover lógica de filtro específico ('0000023425') em produção
  • FOR ALL ENTRIES: Sempre verificar se tabela não está vazia antes
  • CLEAR work areas: Antes de reusar para evitar dados residuais
  • SORT antes BINARY SEARCH: Obrigatório ou pode não encontrar
  • Variáveis globais: tg_alv e tg_alv_2 necessárias para USERCOMMAND

🚀 Melhorias Sugeridas

  1. Remover cliente hardcoded ou tornar parametrizável
  2. Adicionar mais validações de entrada
  3. Criar mensagens de sucesso após salvamento
  4. Adicionar LOG de alterações
  5. Permitir edição de mais campos no ALV
  6. Adicionar filtros adicionais (status, tipo cliente)
  7. Exportar para Excel
  8. Variante padrão para usuários
